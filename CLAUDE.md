# Jev proof check

Checks a whole waste trip's proof with TypeSafe's Jev model: loading photos, unloading photos and weigh bills, against the vehicle number and quantity typed in. A trip runs either tare first (tare → loading → gross → unloading: weighings at least `min_gap_tare_first` apart, every loading photo between them, every unloading photo after gross) or gross first (loading → gross → unloading → tare: weighings at least `min_gap_gross_first` apart, every loading photo before gross, every unloading photo between gross and tare), give or take `clock_slack` (`proof_check.Limits`, 60/10/5 min, changeable per run); the order comes from the final slip's times. Weighings on different days more than `max_overnight_gap` (720 min) apart mean a stored tare, not weighed on this trip (`weigh_day`); nearer, the trip ran across midnight. Times and net weight come from the final slip (both weights); first slips only count for the vehicle number, handwritten notes are ignored. One clear matching plate per kind of photo is enough. When the plant's location is given as input (`--plant`, the page, or `trip.json`; never hard-code it), unloading photos' GPS stamp positions are read to four decimals and must place one photo within `plant_radius` (500 m) of the plant (`plant_check`): degrees and two decimals as Choices, then the Lat/Long line is found with a Box question (`jev-preview`), cut out, and the four-decimal value picked from 100 candidates (`read_line`). For a Verra project trip (`--verra`, the page's tick box, or `"verra": true` in `trip.json`), the final slip must have a material entered (`material`: whether, not what; blank, EMPTY or LOAD is a problem, no material field goes to a person) and carry the weighbridge's own stamp (`weighbridge_seal`, and its name surely matching the slip's heading, `weighbridge_name`; an unsure name goes to a person) (`verra_checks`, `seal_checks`); our company's stamp isn't checked, but its name (`OUR_COMPANY`, set once in code) is sent as `our_company` so that stamp isn't taken for the weighbridge's. Images reused from other trips (`ImageIndex`) and a vehicle on two trips at once (`overlap_checks`, in `tools/check_trip_folders.py`) are flagged. Every check is in one of three parts (`PARTS`, `PART_OF`), each with its own verdict (`decide_parts`): **real** (plates and bills match the typed number, weighing order and gaps, tare weighed on this trip, Time In with the tare, photo timing and same day, photos and bills taken directly, at the plant, no reused image or overlapping trip), **docs** (each kind of image added, vehicle and GPS stamp in every photo, final slip, net weight, gross heavier than tare) and **verra** (material and stamp; only on a Verra project trip). A missing kind of image also asks a person in the real part (its plate or times), so real never passes on nothing. The trip's verdict is the worst part's. Nothing is rejected automatically: a failed check flags its part ("Flagged: problem found"), an unsure one asks a person ("Flagged: please check"), and a person accepts or rejects each part on the page. See README.md for what it does and how to run it.

## Working on this project

- Before planning any new check or feature, ask the user: "Is it for Verra or not?" (Verra project trips only, or every trip). A Verra-only one uses the existing switch (`verra` through `analyze_trip` and `trip_checks`; the page's **Verra project** tick box, `--verra`, `"verra": true` in `trip.json`), and its questions are asked only when the switch is on, left out of `question_version` otherwise, as `VERRA` is. A new check also needs its part in `PART_OF` (`check` fails without one).
- Use the `typesafe-ai` skill (plugin `typesafe@typesafe-ai`) for any change that touches Jev questions, state, models or the API. Follow it: read the relevant live docs at https://docs.typesafe.ai (append `.md` to a page path) before changing an integration, rather than relying on memory.
- Layout: `proof_check/` is the checks, in the order its modules build on each other: `questions`, `images`, `trip_rules` (every check, `PART_OF`, `Limits`, thresholds), `inputs`, `verdict`, `ask_jev` (`analyze_trip`), `__main__`. `proof_check/__init__.py` re-exports every module's public names, so `proof_check.X` works. A test that patches a value has to patch the module that uses it (e.g. `proof_check.ask_jev._keyring_key`, `proof_check.questions.OUR_COMPANY`). `verifier/` is the gw_sales service, `tools/` holds the trip-folder runner, the accuracy report and the test page, and `examples/`, `experiments/` and `docs/` hold the rest. Run everything from the project folder, tools as modules: `.venv/bin/python -m tools.check_trip_folders …`, `-m tools.measure_accuracy`, `-m tools.test_page.server`, `-m proof_check`, `-m verifier`.
- Python lives in `.venv/` (`typesafe-sdk` 0.7.5, Pillow, pillow-heif for real HEIC photos; the verifier service in `verifier/` adds `requirements-verifier.txt`, and its tests `requirements-dev.txt` with moto; the server image installs only the first two). Run code with `.venv/bin/python`.
- Run the offline tests after any change: `.venv/bin/python -m unittest discover -s tests -v`. They use a fake Jev API and need no key. The verifier's (`tests/test_verifier.py`) use a fake gw_sales and the dev Postgres on 127.0.0.1:5433 (`jev-verifier-db` container, README); they are skipped when it isn't running. Leave the other Postgres on 5432 (`postgres18`) alone: it isn't this project's.
- The API key lives in GNOME Keyring (`secret-tool`, attributes `service typesafe account api`), read by `proof_check.api_key()`. Never look it up, print it, or write it to a file, the environment or the test page (`tools/test_page/page.html`); pass it straight to `TypeSafeClient(api_key=...)` server-side.
- Questions are defined once in `proof_check/questions.py` (`QUESTIONS` per slot: `photo` for loading and unloading photos, `bill`; `REPORT`); the tools, the verifier and the tests reuse them. Regenerate `examples/playground/*-questions.json` from `QUESTIONS` after changing them. Keep rules and calculations (rotation, pass/fail/review decisions, the weighing order, gaps, photo timing and distances) in code, not in questions. The place questions (`PLACE`) are only asked of unloading photos when a plant is given, and are left out of `question_version` otherwise so older saved answers stay valid; the plant itself is never sent to Jev. Don't ask for the third or fourth decimal as a digit: Jev misread them, even on the cut-out line; picking a whole candidate value works (19 Oct 2026 runs). The Verra questions (`VERRA`: `material` and the seal questions `SEAL`) are likewise only asked of bills on a Verra project trip, with `OUR_COMPANY` sent as `our_company`; both count in `question_version` only then. The weighbridge question (`WEIGHBRIDGE`: `weighbridge_entered`) is only asked of bills when a weighbridge is entered, with its name sent as `weighbridge`. It counts in `question_version` and `answer_key` only then, so older saved answers stay valid. The box and pick questions are built in code (`LINE`, `pick`), not in `QUESTIONS`, and count in `question_version` with `place`. Bills come in two layouts (a time with each weight, or only Time In/Time Out); both are asked about and `weighings` picks.
- Jev can't transcribe text: the typed vehicle number and quantity (`quantity_kg`) go in the state and Jev judges whether the plate or bill shows them. `net_weight` is only asked when a quantity is typed. Don't list `same` first in a number question (Jev leans towards the first option).
- Image input is experimental in Jev and needs the `TypeSafe-Danger-Zone-Images: true` header (`proof_check.HEADERS`).
- Every bill is cut to its slip before it is read (`SLIP` Box question on `BOX_MODEL`, `find_slip`, `cut_slip`, in `analyze`), then turned upright; the cut counts in the bill's `question_version`. It made small slips readable (23 Oct 2026 test); don't skip it on a low box confidence, the cuts were right anyway.
- A flagged check's `detail` is the reason a person reads on the page: one plain sentence saying what is wrong or unclear, in which image, and what to look at; an unsure one says how sure Jev was and which value was unclear. Give it the images to look at (`images`) and, when another check is flagged for the same reason, the same `cause` (`proof_check.check`), so the page shows them as one.
- The verifier (`verifier/`) checks gw_sales disposals with `analyze_trip`. It pins the Jev versions (`verifier/standards.py`: `MODEL`, `BOX_MODEL`, passed as `box_model`) and picks the limits by the trip's IST date (`STANDARDS`: add an entry from a date, never edit one in use). Table changes are new numbered files in `verifier/migrations/`, never edits to an applied one. Its flags group checks by `cause`, with `code` = the check key and severity from the part (`disposal_check.SEVERITY`). Comparisons with other disposals (`verifier/compare_disposals.py`: `reused`, `same_moment`, `overlap`, `same_file`, all in the real part) use each disposal's latest request, found by its vehicle and IST trip date ±1 day, and skip one whose latest request has no analysis yet (`database.others`). Entered data is checked in `verifier/entry_checks.py`. Every gw_sales time is UTC (one without a time zone is local, IST, as record 78050's were), so convert it with `standards.ist_time` before comparing with photo stamps (which are IST). `collectionDate` is the pickup date, and every collection photo must be stamped on that day. Images and photo times are compared whatever the quantity: the user dropped the same-quantity filter on 29 Oct, after it missed 173186's collection photos (copies of 172929's unloading photos) and prevented no wrong flags on 19 or 23 Oct. `overlap` uses the photos' `busy_time`, not the weighings, because one morning tare is printed on every slip of the day.
- Confidence thresholds (`CONFIDENT`, `YES`, `NO` in `proof_check/trip_rules.py`, and `ROTATE` for turning an image in `proof_check/ask_jev.py`) are placeholders. Choose them from `tools/check_trip_folders.py` and `tools/measure_accuracy.py` reports on real images, per question group and by risk, as the TypeSafe confidence docs advise.
- The verifier runs on the user's own server (dev first) with `deploy/docker-compose.yml`, deployed by GitHub Actions only from `main` (`.github/workflows/deploy-prod.yml`, no approval) through the self-hosted runner on greenworms-server, taking over the `jev-verifier` stack (port `VERIFIER_PORT` in the env file, 8080 if unset); `test.yml` runs the offline tests on other branches and pull requests. Its secrets live only in `/etc/jev-verifier/dev.env` on that server (root, readable by the runner's group), never in the repo, GitHub, chat or image. The image holds only `proof_check/`, `verifier/` and their requirements (`.dockerignore`). The photos are read with a read-only S3 key, since the server isn't on AWS. moto is in `requirements-dev.txt`, not the image.
- `trips/` holds real trip folders (real records: phone numbers, driver names) and a hand-read `truth.jsonl`; it, `eval/` and `mockups/` are gitignored. Never commit or publish them. Saved Jev answers in `eval/answers-<model>.json` let `tools/check_trip_folders.py --cached` re-check a day for free after a rule change.
